# Streamlit Community Cloud

## Публикация

1. Разместите проект в GitHub-репозитории: нужны `src/`, `pyproject.toml`,
   `requirements.txt`, `streamlit_app.py`, `.streamlit/config.toml`.
   Примеры и документацию также можно включить. Не публикуйте пользовательские
   таблицы, экспортированные сессии, `outputs/`, виртуальные окружения и secrets.
2. В Community Cloud выберите **Create app**, репозиторий и нужную ветку.
   Main file path: **streamlit_app.py**.
3. В Advanced settings выберите **Python 3.12**. Секреты для работы не нужны.
   Не задавайте `WTC_STORAGE_MODE=local`: это режим одного локального капитана.
4. Нажмите Deploy. Корневой `requirements.txt` установит пакет из `src/`
   и зафиксированную проверенную версию Streamlit 1.64.0.
5. Откройте опубликованный адрес в двух независимых браузерах. Загрузите разные
   названия команд, начните паринги, сделайте разные баны и проверьте отдельное
   восстановление/скачивание сессии. Затем проверьте импорт скачанного JSON.

Публикация в аккаунте владельца выполняется отдельно; подготовка репозитория
не означает, что приложение уже размещено в Community Cloud.

## Изоляция пользователей

По умолчанию (`WTC_STORAGE_MODE=session`) таблица, политики, контроллер,
генератор случайных чисел и автосохранение принадлежат `st.session_state`
конкретного подключения. Общего файла автосохранения и общего кэша данных нет.
Идентификатор из импортированного JSON не используется как ключ серверного
хранилища: даже две копии одного файла продолжаются независимо.
Статическая раздача файлов отключена. Сервер не пишет пользовательские сессии
на диск в этом режиме. Данные всё равно обрабатываются в памяти облачного сервера.

Автосохранение переживает обычные действия и перерисовки внутри сессии,
но не гарантирует восстановление после обновления страницы, потери подключения,
сна приложения или перезапуска сервера. Для продолжения скачайте **Скачать
сессию JSON**, затем загрузите файл через **Восстановить сессию**.
Экспорт содержит исходные оценки, политики и наш незавершённый скрытый выбор;
передача файла другому человеку передаёт ему эти данные.

Это изоляция браузерных сессий, а не учётные записи. Между устройствами нет
автоматической синхронизации. Долговременное облачное хранение потребует
авторизации и отдельной БД с проверкой владельца каждой записи.

## Локальная проверка облачного режима

```powershell
$env:WTC_STORAGE_MODE = 'session'
.\.venv-ui\Scripts\python.exe -m streamlit run streamlit_app.py --server.address=127.0.0.1
```

Команда `wtc-assistant` сохраняет прежнее поведение: режим `local` и файловое
автосохранение для одного капитана, если режим не задан явно. Переменная
`WTC_AUTOSAVE_PATH` действует только в режиме `local`.

## Проверки и ресурсы

```powershell
.\.venv-ui\Scripts\python.exe -m pytest -q
```

`tests/assistant/test_cloud.py` проверяет разные AppTest-сессии, независимые
названия/истории/RNG/восстановление, отсутствие доступа к старому локальному
файлу и конкурентную запись контроллеров с одинаковым импортированным ID.
AppTest-сценарии чередуются; конкурентное сохранение проверяется потоками.

Проверка 29 сентября 2026 на Windows / Python 3.12.14: в общем прогоне
106 тестов прошли, один новый UI-сценарий остановился на отключённой кнопке
восстановления. Сценарий исправлен: теперь сначала подтверждает замену сессии,
как требует интерфейс. Повторный запуск всех трёх тестов `test_cloud.py`:
**3 passed in 82.72s**. Все 104 прежних теста прошли в общем прогоне;
неисправленных падений нет. Проверены `pip check`, разрешение зависимостей
из `requirements.txt` (dry run) и сборка wheel. Для локальной сборки пришлось
добавить отсутствующие setuptools/wheel; повторная сборка успешна.
Linux CI добавлен в `.github/workflows/tests.yml`, но ещё не запускался.
Фактическое развёртывание и нагрузочная проверка в Community Cloud не выполнялись.

Память для политик выделяется каждому пользователю отдельно. Одновременные
расчёты делят CPU сервера и могут идти медленнее локальных. Не заявляется
фиксированное число поддерживаемых пользователей: лимит нужно измерить на
целевом экземпляре Community Cloud. Готовые политики позволяют пропустить
повторный расчёт. Для большой аудитории потребуется отдельный сервис расчётов.
